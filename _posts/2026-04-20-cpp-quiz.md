1. What is the value of `x` after the following code is executed?
    ```cpp
    int x = 0;
    x = x++;
    ```

    <details><summary class="details-summary">Answer/Explanation</summary>
    <div class="details-body" markdown="1">
    `0`
    
    First, `x++` evaluates to `0` (returns old value).  
    Then the increment side effect makes `x` become `1`, but assignment writes the old `0` back, so the final `x` is `0`.
    
    [godbolt link](https://godbolt.org/z/MdEKWscqq)
    </div>
    </details><br />
    

1. What is the value of `x` after the following code is executed?
    ```cpp
    int x[2] = {0,1};
    x[0], x[1] = x[1], x[0];
    ```

    <details><summary class="details-summary">Answer/Explanation</summary>
    <div class="details-body" markdown="1">
    `{0, 1}`

    The comma operator executes each expression left-to-right, returning the right most value. 
    `x[0]` is not executable, `x[1] = x[1]` is a no-op, and `x[0]` is not executable, so this does nothing.

    _Why doesn't this get parsed as `x[0], x[1] = (x[1], x[0])`, so the result would be `{0, 0}`?_

    The assignment operator has higher precedence than the comma operator.
    </div>
    </details><br />


1. Given the following function `display`, what is the result of passing each of the following `vector<string>`s into `display`?
   {% sidenote 'fix' "Edit: this question is a bit defunct nowadays, since it looks like this has been fixed since GCC 15. If you still want to play along, pretend this is clang." %}
    ```cpp
    void display(const vector<string> &str_vec) {
        cout << str_vec.size() << endl;
        for (const string &str : str_vec) {
            cout << str << endl;
        }
    }
    ```

    ```cpp
    {% raw %}
    vector<string> foo{{"hello", ",", "world"}};
    vector<string> bar{{"hello", "world"}};
    vector<string> baz{{"hello", "hello"}};
    {% endraw %}
    ```

    <details><summary class="details-summary">Answer/Explanation</summary>
    <div class="details-body" markdown="1">
    There is no `string` constructor that takes in 3 `const char*`s as input, so
    `foo` is actually constructed as the list `["hello", ",", "world"]`, and
    `display(foo)` results in:
    ```
    3
    hello
    ,
    world
    ```

    `display(bar)` results in an error because clang tries to call the 
    ```cpp
    template< class InputIt >
    basic_string( InputIt first, InputIt last,
                  const Allocator& alloc = Allocator() );
    ```
    constructor with `"hello"` and `"world`" as the arguments. These two strings are likely
    stored in unrelated locations in the code, so when clang tries to traverse from `first` to `last`,
    it causes a runtime error.

    `display(baz)` results in:
    ```
    1
    ```
    (probably, maybe, depends on the implementation...).


    clang will call the same constructor as above, but this time, `"hello"` and `"hello"` should
    be the same pointer, so when clang iterates between them, it just makes the empty string `""`.

    [godbolt link](https://godbolt.org/z/b8neEqEfn)
    </div>
    </details><br />


1. What is the output of
    ```cpp
    int foo = 1;
    cout << foo["bar"] << endl;
    ```

    <details><summary class="details-summary">Answer/Explanation</summary>
    <div class="details-body" markdown="1">
    `a`

    `array_ptr[index]` and `index[array_ptr]` both desugar to just
    ```
    *(array_ptr + index)
    ```
    so either syntax does the same thing, and
    ```
    "bar"[1] == "a"
    ```
    </div>
    </details><br />


1. What is the output of the following?
    ```cpp
    struct Bit {
        int b : 2 = 1;
    };

    int main() {
        Bit bit;
        cout << ++bit.b << endl;
    }
    ```

    <details><summary class="details-summary">Answer/Explanation</summary>
    <div class="details-body" markdown="1">
    `-2`

    Here, `b` is a [bit-field](https://en.cppreference.com/c/language/bit_field) with an explicit width of 2 bits.
    Because `b` is an `int` (not `unsigned`), the possible range of values is `[-2, 1]`, so when we increment `b` from 1,
    it overflows back to `-2`.
    </div>
    </details><br />


1. What does `const` modify in the following: the `int`, or the pointer to the `int`?
    ```cpp
    int const *ptr;
    ```

    <details><summary class="details-summary">Answer/Explanation</summary>
    <div class="details-body" markdown="1">
    The rule for `const` is:

    _const modifies what is on its left. Unless there is nothing on its left, in which case it modifies what’s on its right._

    So, the `const` here modifies `int`.

    This rule can lead to confusion, which has created two opposing style preferences for how to `const` your types,
    known as the "East Const" vs "West Const" style. There are plenty of discussions about this online, but I'll just link
    [this one](https://hackingcpp.com/cpp/design/east_vs_west_const).
    </div>
    </details><br />


1. What is the output of the following? Why?
    ```cpp
    void print(int &x) { cout << 1; }
    void print(int &&x) { cout << 2; }
    void print(const int &x) { cout << 3; }
    void print(const int &&x) { cout << 4; }

    int main() {
        int a = 3;
        print((const int)a);
        print((const int)1);
        print(4);
    }
    ```

    <details><summary class="details-summary">Answer/Explanation</summary>
    <div class="details-body" markdown="1">
    222

    In each case, the argument is temporary, either because the argument is a literal or because of the casting.
    As such, each argument here is a [_prvalue_](https://en.cppreference.com/cpp/language/value_category#prvalue).

    A temporary can't bind to an lvalue reference (aka `int &`), so they bind to rvalue references instead (aka `int &&`).

    The `const` goes missing here becase, as stated in [the cpp standard](https://timsong-cpp.github.io/cppwp/n4659/expr#6),

    _"If a prvalue initially has the type cv T, where T is a cv-unqualified non-class, non-array type, the type of the expression is adjusted to T prior to any further analysis."_

    `int` is a built-in, so the `const` can be dropped.
    
    [godbolt link](https://godbolt.org/z/5c733fbT6)
    </div>
    </details><br />

1. Given the struct below, what is the size of `foo`?
    ```cpp
    struct foo {
        uint8_t a;
        uint16_t b;
        uint8_t c;
        uint32_t d;
        uint8_t e;
    };
    ```

    <details><summary class="details-summary">Answer/Explanation</summary>
    <div class="details-body" markdown="1">
    16 bytes

    I'm actually going to link the [godbolt link](https://godbolt.org/z/cx9KTE9Td)
    before the explanation this time, since that might just explain it better than me.
    (Pro tip: the `pahole` function in godbolt is super helpful for struct packing!)


    Here is [a longer post about structure packing (technically for C, but it also mostly applies to C++)](http://www.catb.org/esr/structure-packing/), but tl;dr, each member wants to be aligned to its width, so we get the following calculation:

    ```
    struct foo {
      // a is 1 byte and takes up byte 0 of the struct
     	uint8_t                    a;

      // b is 2 bytes, so it must be aligned to an even byte,
      // and it takes up bytes 2-3 of the struct
     	uint16_t                   b;

      // c is 1 byte and takes up byte 4 of the struct
     	uint8_t                    c;
      
     	// d is 4 bytes and must be 4-byte aligned,
      // so it takes up bytes 8-11 of the struct
     	uint32_t                   d;

      // e is 1 byte and takes up byte 12 of the struct
     	uint8_t                    e;
      
     	// a struct has the alignment of its widest member, which is 4 here,
      // so we round up from 13 to 16
    };
    ```
    </div>
    </details><br />

1. What is the output of the following code?
    ```cpp
    #include <iostream>

    struct A {
        A() { std::cout << "A\n"; }
        ~A() { std::cout << "~A\n"; }
    };

    int main() {
        std::cout << sizeof new A << std::endl;
    }
    ```

    <details><summary class="details-summary">Answer/Explanation</summary>
    <div class="details-body" markdown="1">
    `8`

    As you'd expect, `sizeof (A*)` is 8 bytes, but why don't we see `A` get constructed and destructed?

    From [the trusty C++ standard](https://timsong-cpp.github.io/cppwp/n4140/expr.sizeof)

    _"The sizeof operator yields the number of bytes in the object representation of its operand. The operand is either an expression, which is an unevaluated operand..."_

    so `new A` never actually gets evaluated!
    </div>
    </details><br />

1. In the following code:
    1. How many times is `foo`’s parameterized constructor called?
    1. How many times is `foo`’s copy constructor called?
    
    ```cpp
    struct foo {
        int x;
        // Parameterized constructor
        foo(int _x) : x(_x) {}
        // Copy constructor
        foo(foo &other) : x(other.x) {}
    };

    struct bar {
        foo x;
        foo y;
        bar(foo _x, foo _y) : x(_x), y(_y) {}
    };

    int main() {
        foo x{1};
        foo y{2};
        bar{x,y};
        return 0;
    }
    ```

    <details><summary class="details-summary">Answer/Explanation</summary>
    <div class="details-body" markdown="1">
    1. The parameterized constructor is called **twice**, for `foo x{1}` and `foo y{2}`.
    1. The copy constructor is called **four times**, to construct `bar`'s parameters `_x` and `_y` and then to construct its member variables `x` and `y`. 
    </div>
    </details><br />

1. When does each variable get allocated and deallocated?
    ```cpp
    int a = 0;

    void foo() {
        int b = 1;
        static int c = 2;
        {
            int d = 3;
            static int e = 4;
            const int f = 5;
        }
    }

    int main() {
        foo();
        return 0;
    }
    ```

    <details><summary class="details-summary">Answer/Explanation</summary>
    <div class="details-body" markdown="1">
    This is a [storage duration](https://en.cppreference.com/cpp/language/storage_duration#Storage_duration) question!

    `a`, `c`, and `e` have _static_ storage durations, so they are allocated at the start of the program and deallocated at the end of the program. (`a` isn't declared `static` but is one by default by virtue of being global.)

    Everything else (`b`, `d`, and `f`) has _automatic_ storage durations, so they are allocated at the start of their block scope and deallocated at the end of the block scope.
    </div>
    </details><br />


1. What does the following code evaluate to? Why might we choose to write code this way?
    ```cpp
    #include <iostream>

    template<typename T>
    auto f(T t) -> decltype(t.foo(), int{}) { return 1; }

    template<typename T>
    auto f(T t) -> decltype(t + 1, int{}) { return 2; }

    int f(...) { return 3; }

    struct A { void foo(); };
    struct B {};

    int main() {
        std::cout << f(A{}) << f(B{}) << f("hi");
    }
    ```

    <details><summary class="details-summary">Answer/Explanation</summary>
    <div class="details-body" markdown="1">
    `132`

    This is an example of [our good friend SFINAE](https://en.wikipedia.org/wiki/Substitution_failure_is_not_an_error).

    As implied by the expansion of SFINAE (substitution failure is not an error), if an error occurs while trying to substitute in an argument for some template, the compiler will just ignore that function overload instead of erroring.


    We can use this to our advantage by writing code that intentionally errors when we try to substitute in certain types for template parameters. There are a number of ways to do this, but we use `decltype([condition to satisfy], int{})`. If the `[condition to satisfy]` succeeds, the comma operator moves on and returns `decltype(int{})`, which is the correct output type. And if it errors, the function overload is ignored.

    Here,
      1. the first function overload requires that the type `T` has a `foo` member function, which only `A` has.
      2. the second function overload requires that the type `T` has an `operator+`, which only the `string "hi"` has.
      3. the final function overload accepts everything, so `B` ends up calling this.

    For fans of C++20 and beyond, this can be done in a much cleaner way with [concepts](https://en.cppreference.com/cpp/language/constraints). Here is this code translated to use concepts instead:

    ```cpp
    template<typename T>
    concept HasFoo = requires(T t) { t.foo(); };
    
    template<typename T>
    concept CanAddInt = requires(T t) { t + 1; };

    template<HasFoo T>
    int f(T t) { return 1; }
    
    template<CanAddInt T>
    int f(T t) { return 2; }
   
    template<typename T>
    int f(T t) { return 3; }
    ```
    
    </div>
    </details><br />
